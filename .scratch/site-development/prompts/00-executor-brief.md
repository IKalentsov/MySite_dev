## Скиллы

Правило проекта: если задача попадает в область скилла — скилл **загружается**, а не вспоминается.
Раздел «Skills: which ones the agent reaches on its own» в `.dsh/AGENTS.md` объясняет механику.

- Есть инструмент загрузки скиллов (в DSH это `skill`) — загрузи те, что названы в промте задачи.
- Инструмента нет — прочитай `.dsh/skills/<имя>/SKILL.md` напрямую. Рядом со скиллом бывают
  дополнительные файлы (`ADR-FORMAT.md`, `CONTEXT-FORMAT.md`, `DEEPENING.md` и подобные) — они
  читаются по ссылкам внутри `SKILL.md`.

## Git

- **Ветка — первым действием.** Одна задача — одна ветка от актуального `master`. Имя:
  `<тип>/<NN>-<slug>`, где `NN` — номер задачи в карте, `<тип>` — `feat`, `docs`, `test`,
  `refactor` или `chore`. Пример: `docs/02-documents-truth-up`.
- **Коммить** в эту ветку. Сообщения — как в истории репозитория: по-русски, с префиксом.
- **Никогда не пушить.** Ни `git push`, ни `--force`, ни `git merge` в `master`/`develop`, ни pull
  request. Пуш и слияние — владельца.
- Чужие ветки не трогать. Если `master` расходится с `origin/master` — это забота владельца,
  «исправлять» не надо.
- Коммить только файлы своей задачи; чужие незакоммиченные изменения не добавлять.
- Каталог `.scratch/` тебе не принадлежит. Единственное исключение — в конце ты дописываешь
  `## Answer` и `Status: resolved` в файл **своей** задачи. `map.md` не редактируй: строку в
  «Decisions so far» дописывает планер.

## Команды

Выполняются из каталога `backend/`:

| Команда | Зачем |
|---|---|
| `dotnet build MySite.slnx -m:1` | сборка. `-m:1` обязателен: многопроцессная сборка в песочнице упирается в именованные каналы |
| `dotnet test MySite.slnx` | тесты, **только** из `backend/` — там `global.json`. Пока тестов нет, раннер сообщит «Запущено ноль тестов» и вернёт код **5**: это ожидаемо, а не сбой |
| `dotnet ef ...` | миграции, тоже из `backend/` |

## Критерии готовности

- Сборка: **0 предупреждений и 0 ошибок**. Включены `TreatWarningsAsErrors` и четыре анализатора.
- Анализатор не глушится: новых строк в `backend/.globalconfig` быть не должно. Сначала чинится код.
- Версия пакета живёт только в `backend/Directory.Packages.props`; `.csproj` — без `Version`.
- Новая зависимость — только если задача её требует, и с обоснованием.
- Документация отражает изменение: `ARCHITECTURE.md`, если двинулась структура, контракт или стек.

## Особенности среды

- В режиме песочницы `workspace-write` команды `pwsh` падают с
  `SetNamedSecurityInfoW failed (Win32 5): grantWrite(...)`. Это не ошибка твоей команды —
  запроси расширение доступа.
- Запуск приложения, docker-контейнеров и накатывание миграций на живую базу — работа владельца.
  Ты собираешь и тестируешь.

## Отчёт

Верни коротко и по делу: имя ветки и хеши коммитов; список созданных, изменённых и удалённых
файлов; дословный вывод сборки; что осталось за пределами задачи; всё неочевидное или пошедшее не
по плану. Затем допиши `## Answer` в файле своей задачи и поставь там `Status: resolved`.
