# 09 — Стек фронтенда и точные версии

Type: research
Status: resolved

## Question

Нужны точные версии и подтверждение совместимости, прежде чем создавать монорепу. Инвентарь:
Next.js (App Router), React, TypeScript, Tailwind CSS, shadcn/ui, pnpm, Node, ESLint, Prettier.

Что выяснить по первоисточникам (официальные доки и release notes, не блоги):

- Актуальные стабильные версии и их взаимная совместимость: Next.js ↔ React ↔ Node, Tailwind ↔
  PostCSS/плагины, shadcn/ui ↔ Tailwind ↔ React.
- Нужен ли `transpilePackages` для `packages/ui` и `packages/api-client` внутри pnpm-монорепы.
- Что именно пинуется: корневой `package.json` (правило проекта — версия в одном месте),
  `packageManager`, `.nvmrc`/`engines`.
- Тёмная тема: как она делается в актуальной версии Tailwind и shadcn, без самодельных хаков.
- Ограничения среды: Node 24.18.0, pnpm 12.5.1.

Результат — `docs/research/frontend-stack-versions.md` со ссылками на источники, по образцу
`docs/research/i18n-content-storage.md`: отдельно подтверждённое первоисточником, отдельно вывод.

## Answer

Разобрано: **`docs/research/frontend-stack-versions.md`** (442 строки, английский, по образцу
`i18n-content-storage.md` — сначала то, что говорят первоисточники, отдельно вывод и
неподтверждённое). Версии взяты из манифестов npm-реестра (то, что скачает сам пакетный
менеджер), совместимость — из официальных доков.

**Пины:**

| Пакет | Версия | Почему именно эта |
|---|---|---|
| `next` | 16.4.0 | registry latest; `engines: node >=20.9.0` |
| `react` / `react-dom` | 19.3.0 | `react-dom` держит peer `react ^19.3.0` |
| `typescript` | **6.0.3** | `latest` = 7.0.2 (нативный порт на Go), а `typescript-eslint` держит `>=4.8.4 <6.1.0` — типизированный линт с 7.0 просто не заработает |
| `typescript-eslint` | 8.71.1 | |
| `eslint` | 10.12.0 | |
| `prettier` | 3.9.9 | |
| `tailwindcss` + `@tailwindcss/postcss` | 4.3.3 | версии обязаны совпадать |
| `shadcn` | 4.21.3 | только CLI, devDependency; сами компоненты копируются в репозиторий |
| `next-themes` | 0.4.6 | официальный рецепт тёмной темы от shadcn |
| `pnpm` | 12.9.1 | локально стоит 12.5.1 |

**Три вывода, которые меняют следующий шаг:**

1. **`transpilePackages` не нужен.** Доки Next.js 16: Turbopack транспилирует workspace-пакеты
   монорепы автоматически под обоими роутерами. Пустое значение — правильно; триггер пересмотра —
   переход на webpack.
2. **Тёмная тема — две документированные детали, не хак:** явный
   `@custom-variant dark (&:where(.dark, .dark *));` в CSS (по умолчанию Tailwind 4 идёт за
   `prefers-color-scheme`) плюс официальный провайдер shadcn: `next-themes` с
   `attribute="class"` и `suppressHydrationWarning` на `<html>`. Токены — переменные в `@theme` в
   `packages/ui`.
3. **Где пинуются версии — это не факт, а решение.** `catalog:` в `pnpm-workspace.yaml` — тот же
   принцип «версия в одном месте», но сильнее, и он расходится с буквой правила проекта
   (корневой `package.json`). Вынесено в тикет 17.

**Закрытые неопределённости:** локальная среда измерена в этой сессии — Node **24.18.0**, pnpm
**12.5.1**; оба удовлетворяют самым узким требованиям (eslint 10.12.0 хочет
`^20.19.0 || ^22.13.0 || >=24`).

**Что осталось неподтверждённым** (в заметке помечено явно): максимальная версия Node нигде не
документирована, поэтому совместимость — «полы выполнены», а не «поддерживается»; React
неоднозначен, потому что Next.js документирует запуск React Canary, но требует объявлять
`react`/`react-dom` самому — проверяется эмпирически, когда фронтенд появится.
