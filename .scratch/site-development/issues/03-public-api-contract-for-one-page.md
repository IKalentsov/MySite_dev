# 03 — Контракт публичного API для одной страницы

Type: grilling
Status: open

## Question

Одна страница читает две вещи: профиль владельца и опубликованные проекты. Сейчас это два
эндпоинта — `GET /api/v1/profile` и `GET /api/v1/projects`, оба с явным `locale`. Открытые
вопросы:

1. **Один запрос или два.** Составной ответ (`/api/v1/home`) экономит round-trip при SSR и даёт
   странице один источник данных; два эндпоинта переиспользуемы и честнее по ресурсам.
2. **Пагинация.** Правила проекта требуют пагинацию на каждом списочном эндпоинте, keyset
   предпочтительнее offset. У портфолио будет порядка десяти проектов. Либо пагинация делается,
   либо отклонение от правила записывается явно.
3. **Пустой профиль.** Отсутствие профиля — не определённое поведение: 404 или пустой объект? От
   этого зависит, какое состояние рисовать странице (empty или error).
4. **Нет опубликованных проектов.** Пустой список — empty-состояние страницы, не ошибка.
5. **`locale` по умолчанию.** Параметр необязателен (`ru` по умолчанию). Проверить, что 400 на
   неподдерживаемую локаль действительно отдаётся и что это попадает в OpenAPI.
6. **Поля ответа.** Хватает ли текущих (`headline`, `about`; `title`, `summary`, `link`, `year`,
   стек) для первой версии, и где живут Telegram и почта: новые поля профиля или константы
   страницы в `apps/web`.

Решение фиксируется в `Content.http` и, где нужно, в OpenAPI-аннотациях.
