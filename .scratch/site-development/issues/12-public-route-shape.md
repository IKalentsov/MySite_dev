# 12 — Маршруты публичной страницы

Type: grilling
Status: resolved

## Как работать с этой задачей

**Правила работы с проектом — `.dsh/AGENT-TASKS.md`.** Прочитай его первым, до первой правки: там
команды, правила веток, среда и критерий готовности. Ниже — только специфика этой задачи.

- Ветка: `feature/public-route-shape` от свежего `develop`; push ветки и PR в `develop` — работа
  исполнителя, слияние — владельца.
- Критерий готовности этого тикета: решение по каждому из шести пунктов записано в `## Answer` с
  обоснованием, и указано, в каких файлах оно живёт (маршруты, `redirects`, metadata). Это
  тикет-решение: «зелёные тесты» к нему не применяются, но фронтенд-гейты (`lint`, `typecheck`)
  обязаны остаться зелёными, если решение уже во что-то воплощено.

**Условие остановки:** Все шесть вопросов маршрутов решены и записаны в файле тикета: число маршрутов, поведение `/`, переключатель языка, рендеринг и кэш, metadata и OG, показ отсутствующего перевода.

## Question

Первая версия — одна страница. Что именно это значит в маршрутах:

1. **Одна страница или две.** Один маршрут `/[lang]` со всем содержимым или `/[lang]` плюс
   отдельный `/[lang]/projects`. Правило проекта: состояние, которое должно шариться ссылкой,
   живёт в URL.
2. **Что на `/`.** Редирект на `/ru` (308), выбор по `Accept-Language` или отдельная
   landing-страница. `middleware` в Next.js или редирект на уровне маршрута.
3. **Переключатель языка** — элемент интерфейса: ссылка на тот же путь с другой локалью,
   корректные `hreflang` и `lang` на `<html>`.
4. **Рендеринг.** `generateStaticParams` и вопрос, читает ли страница данные на сервере при
   сборке, по ISR или на каждый запрос. Стыкуется с тикетом 03.
5. **Metadata и OG**: заголовок, описание, `og:locale`, язык документа.
6. **Отсутствующий перевод**: fallback из ADR-0005 показываем молча или помечаем в интерфейсе.

## Answer

**Решение принято владельцем 2026-11-16.** Шесть пунктов, по порядку; ниже — что из этого уже
воплощено, а что остаётся тикету 16.

### 1. Одна страница — `/[lang]`

Один маршрут `/[lang]` содержит всё: «обо мне», список проектов и контакт-заглушку. Отдельного
`/[lang]/projects` нет: карта требует одну публичную страницу, а правило «состояние, которое должно
шариться ссылкой, живёт в URL» здесь ничего не требует — все данные одной страницы помещаются на
неё. Если список проектов когда-нибудь вырастет в отдельный экран, это будет новый маршрут и новый
тикет, а не заготовка «на будущее».

Файлы: `apps/web/src/app/[lang]/page.tsx` (тонкий route-файл, реэкспорт `_pages/home`),
`apps/web/src/_pages/home/` (сам экран).

### 2. `/` → 308 на `/ru`, без `Accept-Language`

Постоянный редирект на язык по умолчанию — `ru` (Project facts: русский первый, английский за
переключателем). Никакого выбора по `Accept-Language` и никакого `proxy.ts`/`middleware`: выбор по
заголовку требует `Vary: Accept-Language`, усложняет кэш и делает первый заход
недетерминированным, а язык всё равно переключается ссылкой. `307` из тикета 14 заменён на `308`.

Файлы: `apps/web/next.config.ts`, `redirects()` с `permanent: true`.

### 3. Переключатель языка — ссылка на тот же путь

Переключатель — обычная ссылка `Link` на тот же путь с другой локалью (`/ru/...` ↔ `/en/...`).
Предпочтение языка не хранится ни в `localStorage`, ни в cookie: состояние, которое должно шариться
ссылкой, живёт в URL. `<html lang>` берётся из сегмента `[lang]`, `hreflang` — из
`alternates.languages` в metadata.

Файлы: `<html lang>` и metadata — `apps/web/src/app/[lang]/layout.tsx`; сама ссылка — тикет 16
(`_pages/home` или `widgets`). Маршрутный контракт зафиксирован здесь, UI переключателя — там.

### 4. Рендеринг — динамический, на каждый запрос

Первая версия не делает статическую генерацию и не использует `generateStaticParams`: контент
лежит в PostgreSQL, а в CI базы нет, поэтому сборка либо упала бы, либо запекла бы заглушки.
Страница читает API на сервере при каждом запросе; локаль валидируется в `app/[lang]/layout.tsx`
(`ru` и `en`, иначе `404`). В собранном приложении `/[lang]` уже помечен `ƒ` (server-rendered on
demand). Политика кэша — решение тикета 18; рекомендуемая — `no-store`/динамический рендер.

Файлы: `apps/web/src/app/[lang]/page.tsx`, `apps/web/src/app/[lang]/layout.tsx`; кэш — 18.

### 5. Metadata и OG

`title` — «MySite» до текстов владельца (тикеты 07/16); `description` намеренно не выдумывается и
появится вместе с текстом профиля. `alternates.languages` — `ru`/`en`; `og:locale` — `ru_RU` или
`en_US` по локали, `og:alternateLocale` — другая; `<html lang>` — из маршрута. Metadata собирается
в `generateMetadata`, потому что `og:locale` зависит от `[lang]`.

Файлы: `apps/web/src/app/[lang]/layout.tsx`, `generateMetadata`.

### 6. Отсутствующий перевод — молчаливый fallback

Показываем текст языка по умолчанию, без пометки в интерфейсе. Это уже поведение API
(`TranslationFor(locale)`: запрошенная локаль → локаль по умолчанию → ничего, ADR-0005), и
фронтенду не нужно ничего решать. Пометка «переведено не полностью» потребовала бы, чтобы API
отдавал, какая локаль реально использована; это отдельное изменение контракта, не первая версия.

Файлы: `backend` уже так делает; фронтенд ничего не добавляет.

### Что уже в коде

- `apps/web/next.config.ts` — `permanent: true`, то есть `/` отвечает `308` с `Location: /ru`.
- `apps/web/src/app/[lang]/layout.tsx` — `generateMetadata` с `alternates.languages` и
  `openGraph.locale`/`alternateLocale`; `<html lang>` из маршрута; неизвестная локаль → `404`.
- Ни `/[lang]/projects`, ни `generateStaticParams`, ни `proxy.ts` не добавлены.

### Чем подтверждено

Гейты из `frontend/`: `pnpm lint`, `pnpm typecheck`, `pnpm build` — зелёные. Проверка маршрутов на
`next start`:

```
/     → 308, Location: /ru
/ru   → 200, <html lang="ru">, <link rel="alternate" hrefLang="ru"/"en">, og:locale = ru_RU
/en   → 200, <html lang="en">, og:locale = en_US
/de   → 404
```

### Что это разблокирует

- Тикет 16 — маршрут и metadata зафиксированы; остаётся экран и переключатель.
- Тикет 18 — политика рендеринга (динамически, без статики) и кэша (18 уточняет `no-store`).
